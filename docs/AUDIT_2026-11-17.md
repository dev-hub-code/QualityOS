# Backend, security and concurrency audit — 17 November 2026

Follows the external review of `dev` on 17 November. It covers the code merged since the
[1 November security review](SECURITY_REVIEW.md) and the transaction behaviour the review asked about.
Everything below was checked against the running code and database, not only by reading.

**Summary:** no Critical or High findings. One Medium race was found and fixed (#115). Two Medium items
remain, and both belong with the deferred production work. Three Low items are defence in depth.

## Findings

| # | Severity | Finding | Where | Status |
|---|---|---|---|---|
| 1 | Medium | An OQC started while a dispatch of the same batch was committing failed with "changed by someone else". Locking a batch already loaded in the transaction checked its version instead of re-reading it. | `traceability/service/ProductionService.java` (`lock`), `inspection/service/InspectionService.java` (`inspectProductionBatch`) | **Fixed in #115**: the lock flushes, then refreshes under `PESSIMISTIC_WRITE`; the OQC is sized from the locked batch. |
| 2 | Medium | The sign-in rate limit is held in memory and counted per client address. Guessing one account's password from many addresses isn't slowed, a restart resets the counts, and several backend instances would each count separately. | `common/security/AuthRateLimitFilter.java` | Open; do with production. Add a per-account failed-sign-in counter in the database, or a shared store, before running more than one instance. |
| 3 | Medium | CI has never run because GitHub Actions is disabled on the account. Every result is from local runs. | `.github/workflows` | Open; needs the account owner. |
| 4 | Low | `tenant_logo(p_tenant)` and `gateway_order_tenant(...)` are `SECURITY DEFINER` and don't check the caller. The application role can read any organisation's logo if it knows the organisation's id. Only server code calls them, with a known id, and logos aren't confidential. | `db/migration` (logo and Cashfree migrations) | **Fixed in V53:** `tenant_logo` returns a logo only for the signed-in organisation, or for any when none is set (the email worker); `gateway_order_tenant` answers only when no organisation is set (the webhook). Tested in `OrganizationLogoIT` and `CashfreePaymentsIT`. |
| 5 | Low | `refresh_tokens` has no RLS. | V2 | Kept as the documented exemption (`TENANT_ISOLATION.md`): a refresh token is looked up before its organisation is known, so a tenant policy could only be bypassed, not enforced. Reached only by identity services, and tokens are stored hashed. |
| 6 | Low | `ProductionService.requireInspectable(UUID, String)` was left unused by #115. | `ProductionService.java` | **Removed in this PR.** |

## Checked and found sound

- **Tenant isolation:** 114 tables have a `tenant_id`. In the live database, 113 have RLS enabled, forced, and with a policy; the 114th is `refresh_tokens` (#5).
- **`SECURITY DEFINER` functions:** all 61 pin `search_path`.
  - Every `platform_*` function that returns or changes platform data calls `require_platform_role` or `require_platform_admin`.
  - The rest are job helpers or sign-in helpers that return only IDs, or work under `current_tenant_id()`.
- **SQL injection:** no query is built from request input. The dynamic parts are constants (`PlanLimits`) or sort columns taken from a fixed map (`SerialSearchService`).
- **Request validation:** every `@RequestBody` is `@Valid` except three:
  - two records with no constraints (`EndDowntimeRequest`, `LinkCapaRequest`)
  - the Cashfree webhook, whose HMAC-SHA256 signature is compared in constant time before anything is read
- **Endpoints added since 1 November:** every write endpoint needs a permission, except sign-in, the user's own notifications and support tickets. Platform controllers are guarded at class level.
- **Support access:**
  - A support session gets only `*_VIEW` permissions, without production costs.
  - It can't write: `SupportSessionFilter` refuses every method other than reads.
  - Every read is logged for the organisation.
  - A grant lasts 24 hours, 3 days or 7 days only, and ends when revoked or when the organisation is suspended.
- **Logo upload:**
  - The type is recognised from the file's content, so only PNG or JPEG is accepted, never SVG or HTML.
  - It is limited to 256 KB and served with `nosniff`.
- **Plant restriction:** each manufacturing module has a test showing that a member limited to another plant gets 404, and that list views leave that plant's records out. The modules are work centres, work orders and plans, materials, shop floor, quality gates and rework, downtime, and completion.

## Concurrency coverage

Each test below sends competing requests at the same moment against PostgreSQL.

| Race | Test |
|---|---|
| Two receipts against one purchase order line | `PurchasingIT.concurrentReceiptsCannotOverReceive` |
| Document numbers | `PurchasingIT.concurrentOrdersGetDistinctNumbers` |
| Work orders reserving one lot | `WorkOrderMaterialIT.ordersCompetingForTheSameLotNeverReserveMoreThanItHas` |
| Work orders issuing from one lot | `WorkOrderMaterialIT.ordersIssuingFromTheSameLotAtOnceNeverTakeMoreThanItHas` (new) |
| Shop-floor reports past an operation's quantity | `ShopFloorIT.reportsArrivingTogetherNeverGoPastTheQuantity` |
| Two dispatches of one batch | `DispatchConcurrencyIT.twoDispatchesOfTheSameStockNeverShipMoreThanThereIs` (new) |
| Dispatch against OQC start | `DispatchConcurrencyIT.aDispatchAndAnOutgoingInspectionNeverPassEachOther` (#115) |
| AQL approvals in one switching series | `AqlSwitchingIT.lotsApprovedAtTheSameMomentAreAllCounted` (#115) |

These tests catch races by chance; a pass is evidence, not proof. The locks they exercise are row locks
(`FOR UPDATE` or a pessimistic refresh) taken before any quantity is read.

## Not covered

- The frontend beyond the BFF's header forwarding. `bff.ts` keeps only the last `X-Forwarded-For` hop, so a client can't spoof the address the rate limit counts.
- A penetration test against a deployed instance.
